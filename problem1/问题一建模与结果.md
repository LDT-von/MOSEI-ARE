# 问题一 多模态特征提取与可追溯时序对齐

本章对应赛题Word中“问题1：多模态情感特征提取与时序对齐的数学建模”及“问题1相关内容”四项要求。我们以附件1的100条原视频和原始转写为输入，完成三模态特征提取、共同时间轴、逐样本文件、全量汇总、典型样本展示和复现核验。第一题的重点是特征与原始素材的对应关系。附件2上的情感预测分数属于后续建模，不能证明这里的时间对齐正确。

本文把“情感特征”定义为保留原始时间来源、可供后续情感模型使用的连续表征：文本向量描述上下文语义，语音向量描述能量、音高与声谱等韵律线索，视觉向量描述人脸或场景外观。共同位置 `k` 的三模态特征分别记为 `x^T_(i,k)∈R^384`、`x^A_(i,k)∈R^33`、`x^V_(i,k)∈R^512`。这些向量不是情感标签或情绪概率；其预测效用须在后续任务中另行验证。

本次已经生成100份样本特征。79条通过自动词级对齐筛查；其余21条保留全部原始样本、语义特征与候选时间记录，并屏蔽默认输出中不可靠的时序文本。自动筛查通过不等于经人工确认的词边界正确。

## 1 原有SlotEmo实验与第一题的关系

现有 `exp3_problem1.py` 实际读取附件2的 `aligned_50.pkl`，以已经提取的768维文本、74维语音和35维视觉向量训练情感预测模型。其掩码统一设为有效。它没有对附件1原视频提取三模态特征，也没有保存词、音轨与视频帧的物理时间对应。当前 `exp3_problem1_alignment.json` 仅26字节且不是完整JSON，不能作为全量对齐证据。

原实验结果文件记录：验证集最佳加权F1为0.5196，测试集加权F1为0.5660，测试集Accuracy为0.6341，MAE为0.7207。这些是历史文件中的记录，本次未重跑其预测实验。它们不代表问题一的验证结果，也不足以断言Slot专门化必然造成性能崩塌。

赛题Word表1还明确区分附件2的两套接口：`aligned_50.pkl` 的三模态最多各50个对应位置；`unaligned_50.pkl` 的文本为50个位置，语音和视觉各保留最多500个独立位置，实际长度另见 `audio_lengths`、`vision_lengths`。表2说明 `text_bert` 是BERT整数输入，不是第四种模态。附件2只有预计算数值特征与原始转写，不提供原视频帧、音轨波形或逐词时间戳，因而不能代替本题的附件1处理。

赛题Word内嵌的多模态图标为独立示意样本，用于解释原信号、词时戳与标签如何共享一条时间轴；它不是附件1这100条样本的全量处理证据。本章第9节另用附件1实测样本给出自己的对应图。

Slot Attention权重可以表示输入与隐变量槽之间的关联，但槽编号没有天然的秒数含义，多个槽也可能覆盖同一时间段。本方案先建立可回查的时间轴。若后续保留Slot，应在此基础上研究语义聚合，并以控制实验检查是否保留了必要信息。16个槽不能未经验证就解释成16种心理情感因素。

## 2 样本身份与播放时间

本方案以 `video_id__clip_id` 唯一标识一个样本。逐行读取原始 `label-100.xlsx`，核验100个唯一标识与100个MP4视频一一对应。标签表、每段原视频和输出特征均计算SHA-256；原转写与标签只用于记录身份及来源，没有参与特征提取器训练或筛查阈值选择。附件2的 `id` 则采用 `video_id$_$clip_id` 格式，未来跨附件联接必须先明确转换，不能直接按本方案的内部字符串格式相等匹配。

用PyAV按MP4播放时间戳PTS和time_base解码。播放原点作为该片段的零秒。音频转为16 kHz单声道，逐个解码帧依其时间戳写入波形，并另存采样点可用标记。真实的零幅度静音属于已观测音频；解码覆盖之外的零填充值才是不可用。视觉帧保存实际PTS、解码帧号、分辨率和裁剪框。

这批文件含MP4编辑列表。默认解码遵守其播放时间线；文件头的编码帧数可能包括播放时不出现的预卷帧。因此不以“编码帧数÷帧率”替代有效播放时长。`media_audit.json` 同时记录遵守编辑列表的播放时长和忽略编辑列表时的编码载荷时长。后者用于解释来源差异，不用于正式对齐，也不改变任何原始视频。

设片段有效播放时长为 `D_i`。采用0.2秒共同粒度，定义 `I_(i,k)=[kΔ,min((k+1)Δ,D_i))`，其中 `Δ=0.2 s`、`K_i=ceil(D_i/Δ)`。最后一个区间保留实际尾段；长片段不截成50个位置。单个文件存变长序列，组成批次时再右侧填零，并用独立的 `padding_mask` 标出真实位置。

## 3 文本特征和词级候选时间

原始文字不回写。另建用于强制对齐的规范化转写：统一大小写、略去不发声的标点、把数字变为英文读法；每个规范化词都保留原文字符区间。例如 `2008` 可用于匹配 `TWO THOUSAND EIGHT` 的发音，但输出仍指向原文里的 `2008`。

冻结的Wav2Vec2 ASR模型给出每个声学帧的字符分布。给定转写序列 `c_(1:L)`，CTC强制对齐求使 `B(π)=c_(1:L)` 的最大似然路径 `π* = argmax_π Σ_t log p(π_t|a)`。`B` 表示删除空白标记并合并重复字符。按模型20 ms步长把字符位置映回秒数，再合并为词的候选区间。每个词保存候选起止秒数及字符发射分数均值。20 ms是数值粒度，不是人工测得的词边界误差。

文本编码采用冻结的 `paraphrase-multilingual-MiniLM-L12-v2`。用原文取得上下文token向量，再对与原文字符区间相交的子词求均值，得到384维词向量。长文本用最多126个正文token的窗口、96个token步进；重叠处平均，避免静默截断。本流程取用模型的上下文token表示，并未把整句嵌入的公开性能当作词级质量证明。

## 4 语音特征

在16 kHz音轨上使用40 ms Hann窗、20 ms帧移、1024点FFT、40个Mel滤波器和13个MFCC。每个原生声学帧为33维：13个MFCC、13个一阶差分MFCC，加上对数RMS、过零率、谱质心、85%谱滚降点、基频、周期性和清浊音标记。

基频由50至400 Hz范围的自相关峰估计。周期性≤0.3或RMS≤0.0001时作为非浊音处理，基频设零；零基频本身不表示整个音频模态缺失。尾窗可补零进行计算，但其时间支持只覆盖真实片段范围。窗内解码可用采样比例必须大于0.99才能参与默认对齐。本题未在100条样本上拟合均值或标准差；后续预测若需数据标准化，应仅在规定训练划分上拟合。

## 5 视觉特征

在每个0.2秒区间中心选取实际PTS最近的视频帧。检测到人脸时取面积最大的候选框并扩边15%；检测不到时使用完整画面，并记录 `vision_scene_fallback=True`。若同时出现多张脸，记录候选数；最大人脸不能保证是发言者。

用冻结的ResNet18 ImageNet1K V1官方预处理，取分类头前的512维外观向量。它可提供面部或场景线索，但不是情绪概率，也不是面部动作单元。本次没有验证这个视觉表示单独识别情绪的准确率。实际帧与区间中心距离超过0.101秒才屏蔽该视频位置；不将一次人脸检测失败误写成视频缺失。

## 6 跨模态时间对齐

模态 `m` 的原生特征 `h_(i,j)^m` 有时间支持 `J_(i,j)^m`。文本和语音按与共同区间的实际交叠时间加权：

```text
u_(i,k,j)^m = r_(i,j)^m × | I_(i,k) ∩ J_(i,j)^m |
A_(i,k,j)^m = u_(i,k,j)^m / Σ_l u_(i,k,l)^m
x_(i,k)^m = Σ_j A_(i,k,j)^m h_(i,j)^m
```

`r_(i,j)^m` 表示原生位置可使用。分母为零时，输出零特征与False掩码，不向前或向后臆造内容。视觉直接使用最近实际帧。每个非空权重行的和为1。声学窗可相互交叠，因此权重是对所有有效窗的交叠长度重新归一化，不等于互不重叠的覆盖面积。对齐矩阵只由时间支持与掩码决定，没有用情感标签训练。

原生时间区间和特征一并保存，使检查者可以独立重建共同时间轴上的特征。这是本方案可复核性的关键，比直接声称某张注意力热图“已经完成对齐”更有证据。

## 7 候选对齐的质量筛查

强制对齐即使面对不匹配的转写或纯静音，也可能返回形式上合法的字符路径。因此必须把“算法给出候选时间”和“可用于默认时序文本”区分开。事先固定且不依赖情感标签的规则为：样本平均CTC诊断分数≥0.5，且给定转写与该模型独立贪心识别的有序词匹配比例≥0.5。词匹配比例为两序列最长公共子序列长度除以给定转写词数，容许转写未覆盖的前后话语。

通过样本级筛查后，单词自身分数还须≥0.5才能进入默认时间对齐。未通过的样本或词仍保留原始语义向量和候选时间；默认时序文本设零，`text_mask=False`。`text_candidate` 和 `text_candidate_mask` 专供审计。诊断分数及0.5阈值未经概率校准，不能将筛查通过率表述为准确率。

### 独立自动语音抽查

冻结的Whisper-small对4条视频进行额外识别，仅作诊断，不替换官方转写，也不用于训练或阈值选择。`-3g5yACwYnA__13` 的独立识别包含官方转写，前面还有未覆盖的“that we do”。`-iRBcNs9oI8__7` 的官方转写从“Well, for starters”开始，独立识别却出现“interview...secret will also help you”。`-NFrJFQijFE__2` 的官方文字涉及技术协调，音轨独立识别涉及鹰的听觉与视力。详细原文与识别文本见 `outputs/independent_asr_audit.json`。

`-mJ2ud6oKI8__1` 和 `-mJ2ud6oKI8__2` 的已解码音轨逐声道数值都精确为零，排除了转单声道导致相位抵消的解释。静音上自动识别偶尔产生文字，不能将此类输出当作音频事实。21条屏蔽样本不能整体判定为官方标签错误；可能还包含语音模型误差、剪辑差异与规则偏保守，需按清单复核。

### 效果判定与附件2两种版本的关系

本题目前可量化的是处理完整性和内部一致性，而不是人工真值上的对齐准确率。100段视频都有三模态输出及原始来源；79段通过自动词级筛查，覆盖1627个原文词中的1543个可用词；另外21段含304个原文词，全部保留在原生文本特征与候选记录中，但默认时序文本被屏蔽。这样的屏蔽避免把不可靠的候选时间当作确认的对应关系，也意味着三模态在这21段上并未获得可用的逐词时间对齐。四段独立ASR抽查中，一段通过筛查且识别包含官方转写，另外三段被屏蔽且存在明显不一致或静音；抽查不是随机准确率估计。

附件2的 `aligned_50.pkl` 与 `unaligned_50.pkl` 是同一赛题提供的两套预计算特征接口：前者三模态最多各50个对应位置，后者文本最多50个位置而语音、视觉分别保留最多500个独立位置。它们没有原视频帧、音轨或逐词时间真值，维度也与本章生成的384/33/512特征不同。因此比较两文件的分类F1或回归MAE，只能评价这两套输入接口对同一预测模型的影响，**不能直接证明本章从原视频建立的0.2秒对齐是准确的**。旧SlotEmo仅在 `aligned_50.pkl` 上运行过，尚无同模型、同划分、同随机种子的 `unaligned_50.pkl` 对照结果。

要给本章方法一个可解释的“对齐效果”数值，需要先对分层抽取的原视频人工核对词起止时间和对应帧，再报告词边界绝对误差、落入0.2秒时间格的比例、有效覆盖率及被屏蔽样本的误拒率；最好同固定间隔均分或整体错位等无对齐基线比较。人工标注和这些指标目前尚未完成，不能把79%自动通过率、重建误差或旧模型F1写成对齐准确率。

## 10 文件格式与复现

每个样本为一份不含Python对象的压缩NPZ，使用 `numpy.load(path, allow_pickle=False)` 读取；全量索引见 `outputs/summary_100.csv`，逐样本追溯信息见 `outputs/metadata/<sample_id>.json`。核心字段如下。

| 字段 | 形状 | 含义 |
|---|---|---|
| `grid_intervals` | K×2 | 共同时间区间起止秒数 |
| `text` / `audio` / `vision` | K×384 / K×33 / K×512 | 默认时序特征 |
| `text_mask` / `audio_mask` / `vision_mask` | K | 各模态可用标记 |
| `padding_mask` | K | 单样本真实时间位置，均为True |
| `raw_text` / `raw_text_intervals` / `raw_text_scores` | W×384 / W×2 / W | 原生词特征、候选时间及诊断分数 |
| `raw_text_usable` | W | 能否进入默认时序文本 |
| `text_candidate` / `text_candidate_mask` | K×384 / K | 未筛查的候选汇总，仅供审计 |
| `raw_audio` / `raw_audio_intervals` / `raw_audio_valid` | F×33 / F×2 / F | 原生语音特征、时间支持和有效性 |
| `raw_audio_available_fraction` | F | 声学窗内实际解码覆盖比例 |
| `raw_vision` / `raw_vision_pts` / `raw_vision_frame_indices` | K×512 / K / K | 视觉表示和实际来源 |
| `vision_face_detected` / `vision_scene_fallback` | K | 人脸裁剪或整帧回退 |

这里“raw”指本方法的原生特征，不是未压缩原视频。批次填充示例见 `load_features.py`。问题一自生成维度为384/33/512，与附件2的768/74/35不同，不能直接替换附件2或加载旧SlotEmo权重。

运行环境为Python 3.10.11、PyTorch和TorchAudio 2.6.0+cu124、TorchVision 0.21.0+cu124、Transformers 4.44.2、PyAV 16.0.1，实际导入的OpenCV为4.10.0。文本模型固定修订 `86741b4e3f5cb7765a600d3a3d55a0f6a6cb443d`。视觉使用ResNet18 IMAGENET1K_V1，语音使用WAV2VEC2_ASR_BASE_960H。版本、参数、权重SHA-256和脚本SHA-256记录于 `outputs/run_manifest.json`。详细命令见 `README.md`。

此方案把可追溯时间接口、区间交叠规则、异常保留及明确掩码作为第一题的核心。CTC、MFCC和预训练编码器都是已有工具，不应包装成原创算法。目前没有人工标注的词边界真值，不能报告对齐准确率；本次也未评测情感预测F1、MAE和Pearson。
